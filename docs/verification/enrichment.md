# Enrichment foundation

The queue stores jobs and settings snapshots in the shared database. Default native/HTTP saves create the item and its initial job in one transaction. Unconfigured jobs do not fabricate tags or summaries. Repeated saves preserve existing data and do not enqueue another successful revision automatically.

Claims use SQLite write transactions, a fresh per-claim fencing token and an expiry. Completion requires the live token, worker and unexpired lease, and applies results only to the expected item revision. Three attempts bound retry/recovery; a crash can cause another provider invocation, so exactly-once inference is not promised. Cancellation fences late writes. Generated tags/summary are persisted; model/provider/coverage metadata is stored on the job.

Library route initialization is explicit, immutable through registration, and contains only provider/model/owner_profile. A different profile cannot silently change it. Configure `settings.library_root` consistently, then `settings.enrichment_route` with those fields on the owner. Explicit provider/model calls require Hermes operator trust grants; this code does not read credentials or change those grants. Native chat model changes are independent. Full settings editing, independent tags/summary toggles and regeneration UX remain M3.

The worker uses public `ctx.spawn_task` under a running host loop and is cancelled by Hermes on unload. Only the configured `ctx.profile_name` owner starts it. No custom event loop, unmanaged thread, daemon or scheduler is started. Synchronous registration with no running loop reports `host_loop_unavailable`; actual cold-host behavior is an acceptance gate, not claimed solved. No inference begins without a complete route and compatible facade.

Extraction uses a killable 25-second subprocess with only PATH/LANG/TMPDIR, never inherited provider credentials. Each HTTP(S) redirect resolves and validates all addresses as global, then connects to a pinned validated IP with hostname TLS/SNI. Default ports only, no cookies/proxy environment/compression, 1 MiB response and 30,000 extracted characters. Only HTML/plain text is accepted. The subprocess still has the service account's filesystem authority; this is not an OS sandbox. Source text is untrusted input in a tool-free host structured call; local output checks apply even if provider schema validation is unavailable.

Evidence: test-first missing-module RED for queue, enrichment and worker adapter. Final suite at this task: 58 Python and 10 Node tests passed. Tests cover multi-process exclusive claiming, reused-worker fencing, expiry without recovery, cancellation, revisions, route changes, retry caps, invalid model output and coroutine cancellation. Model outputs are synthetic fixtures, not provider responses. `extract_text('https://example.org')` executed successfully and returned 170 characters from the real public page; no live inference or real user content was used.

Remaining acceptance gates: real configured cold-host supervisor lifecycle, real-model trust/routing/vision (requires approval), and broad redirect/DNS/timeout adversarial coverage plus independent security review. M1 is not complete merely because the isolated queue and generator tests pass.
