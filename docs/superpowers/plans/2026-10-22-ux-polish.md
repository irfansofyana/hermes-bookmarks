## Tasks and ownership

1. Presentation: test-first form/detail/dialog refinements and scoped `ui/library-polish.css`. Keep labels/control semantics used by existing callers/tests. Verify real SDK styles and wide/narrow focus/action reachability. No state-machine rewrite or new editor dependency. Controller wires the new CSS inventory.
2. Selection: new `ui/library-bulk.js` over existing revision-checked item update/trash/restore APIs. No new batch scheduler, schema, or hidden unbounded server job. At most 100 explicit IDs; readable review fetches current full records before explicit Apply, freezes those revisions and action. One sequential mutation per item; no automatic retry/rebase. Report applied/conflict/failed/skipped/uncertain/unprocessed separately. Stop/unmount prevents further dispatch, retains admitted result in the owning in-memory report. A lost acknowledgement stops remaining writes and tells the user to inspect saved state. This is not all-or-nothing; committed changes remain.
3. Library integration: select visible page, retained selection, clear/review actions and View item notice. Refresh current filters after mutations, never a stale closure. Scope/unmount guards prevent old operation publishing into new backend/library. No source/network/inference for bulk actions.
4.
